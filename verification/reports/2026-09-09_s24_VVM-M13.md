## Implemented scope

- deterministic on-device generators seed a representative 10,000-position
  analysis, a 100,000-position large analysis, and a summary-only 10,000-activity
  library without committing large generated fixtures;
- opt-in reference-device tests measure local analysis load, selected-position
  latency, continuous selection update rate, large-activity and large-library
  capacity, memory behavior, and recording UI responsiveness;
- chart rendering is bounded to 2,000 presentation points while retaining first,
  last, and bucket extrema;
- route rendering is bounded to 5,000 presentation points with each route
  segment and its endpoints retained independently;
- full source and logical analysis arrays remain unchanged and continue to own
  inspector, synchronization, and route-selection semantics;
- the MapLibre adapter caches unchanged full/range GeoJSON, so a cursor-only
  selection updates the marker without recreating route geometry;
- API 26-compatible permission setup supports an automated minimum-version core
  workflow; current-target foreground-service continuation is explicitly covered.

## Profile before optimization

The initial 100,000-position S24 run loaded and remained functional without OOM,
but private-dirty memory reached 396,359 KiB. Inspection of the measured path
showed that all 100,000 chart/map points were handed to renderers and unchanged
range GeoJSON was recreated on every cursor update.

After the presentation-only limits and route-geometry cache were added, the same
large fixture completed at 348,491 KiB private dirty, a 47,868 KiB (12.1%)
reduction. No source precision, logical lookup data, active-elapsed-time semantics,
or discontinuity boundary was removed.
