## Implemented scope

- one RADM-owned interaction state contains the canonical selected active-elapsed
  time, coordinate mode, and active-elapsed-time range boundaries;
- precomputed in-memory indexes provide binary-search time → distance, distance →
  time, and time → pace/speed/elevation/cadence lookup and interpolation;
- interpolation does not cross route-segment or step-counter-epoch boundaries;
- each applicable Vico graph has a Compose-owned touch/drag overlay and persistent
  cursor driven by the common RADM state rather than Vico marker state;
- the selected-position inspector and every graph cursor use the same logical
  active-elapsed-time position;
- the shared Distance / Active Elapsed Time control preserves canonical selection
  and range, and updates every graph axis consistently;
- touch-appropriate start/end sliders update one common range, clamp an excluded
  selection to the nearest boundary, identify the corresponding local route
  subsection, and provide an explicit full-range reset;
- Vico chart-series projection is memoized by data, coordinate mode, and range so
  graph selection does not rescan the activity on every pointer movement;
- interaction indexes are built off the main thread after the M10 local dataset is
  loaded, and the high-frequency path performs no Room or network access.

Map marker rendering and map-driven selection remain M12 scope.

## Early performance profiling

The deterministic JVM profiling fixture builds a loaded 100,000-position analysis
dataset and performs 10,000 synchronized selections after disabling all repository
reads. Its focused JUnit execution completed in approximately 0.4 seconds on the
development host, including fixture and index construction.

This result confirms the intended local logarithmic lookup path and begins the
M11 profiling requested by `RADM-IMP_R00.md`. It is not substituted for the
reference-device percentile latency or effective rendered update-rate evidence
required by `VVM-PERF-001/002`; those remain formal M13 work.
